# Lume case collaboration — unit 3

Implemented the accepted case collaboration contract on `feat/lume-agent-canvas`, preserving the intentional dirty tree and the preceding functional repairs. This unit adds working shared tasks, private requester delegation, cross-office notifications, the enforced case Lume policy, a home-context Honorários projection and authoritative case activity. The case UI has real handlers in pt-BR on desktop and 390 px. The small ResearchCaseLinker failed-load draft regression is also repaired.

The explicit implementation role and available p3-mode instructions governed this work. The already-known missing `agents/p3-agent.md` was not searched again. No nested agents, architecture tournament, cosmetic review round, commit, PR or deployment was performed.

## Implemented behavior

**Shared tasks.** Existing `agenda_activity` rows stay personal, including rows with a case link. New shared tasks explicitly use `visibility='case'`, task kind and the server-resolved case office. Their shape excludes CRM and calendar fields. Narrow `k5_case_tasks_list/get/create/update` capabilities authorize current participants without granting general agenda or CRM access. Personal agenda operations and office exports exclude shared rows.

Creation has a stable idempotency identity and immutable input hash: concurrent retries create one row and one transactional event; conflicting reuse is rejected. Updates lock the row and require its current version. Assignees must still have the case and every retained source permission, even when an edit leaves the assignee unchanged. The UI supports creation, assignment, dates, states, editing and completion. A stale save preserves the draft, and “Atualizar versão e manter rascunho” refreshes only its version before an explicit save.

Agent task text is generated from the recorded person request through the existing shared-writing owner. The exact proposed fields and durable source policy are reviewed before transactional publication. Replays reauthorize current case and source access without duplicating writes or events. Human edits retain source guards instead of laundering restricted contributions.

**Delegation.** Shared tasks remain in the case office. Each requester's conversation and delegation receipt remain in that requester's home office; only that requester receives the private conversation link. Existing admission, capacity, lease and retry protections remain. The initial delegated message now records a real `content_submission`, its source inputs, content policy, generation/scope metadata and provenance in the same transaction. The chat prompt can therefore admit the request normally and excludes it after source revocation. Normal personal delegation remains unchanged.

**Notifications.** Existing task services capture transactional events. The worker projects intended eligible recipients into their home-office inboxes using their home preferences and subscriptions, without creating source-office membership. Event identity no longer assumes recipient and event offices coincide. Current task/source permission and assignment eligibility are checked during projection, inbox/unread presentation, destination resolution and push delivery. Shared destinations open the actual case task. Stale assignment, revoked access, unrelated personal tasks and forged private events are excluded. Due reminders support cross-office recipients while retaining the source task's office binding.

**Case Lume policy.** `vault_case.lume_enabled` is the single policy field, defaults enabled and is controlled by the human case owner. Its prototype copy is preserved. Participant and owner agent work is denied while disabled. Checks cover original and later model admission, stored proposals/consumed receipts, capability execution, task delegation, queued runs and retries. Case identity is resolved from supplied resources even when `caseId` is omitted. Bound-case access is rechecked after participant revocation. Selected sources and broad agent case/document/knowledge discovery filter or deny disabled cases before model use. Re-enabling restores currently authorized work. Human reads/edits and independent portal publication remain available.

**Honorários and activity.** The fee projection calls the existing Honorários service in the person's home context and filters the linked case. It includes allowed amounts, installment state, totals and existing creator-management/consultation links; it excludes CRM identity, private financial notes/pricing and unrelated balances. No second finance storage or guest finance capability was added. Recent activity composes real page versions, case-bound membership/policy audit, accessible live files, and shared task creation/current-state timestamps. Every item uses current resource visibility, including historical page-version policy and retained task source guards. It makes no claim to reconstruct intermediate task transitions or deletions and includes no private chats, approvals or delegation transcripts.

**Case UI and carry-over.** Tasks, Honorários and activity are integrated with the existing pages, files, processes, references, annexes, participants and folder controls. Owner policy changes use the real endpoint; participants see a disabled control. Components key their local state by case, fence loads and hide stale data/errors. Loading, empty, failure and retry states are present. The existing ResearchCaseLinker clears its visible draft immediately on case change, keeps its version-bound draft cache and restores cached text only after the selected case's identified successful load. Its regression holds actual HTTP responses and proves failed A loading cannot display B's draft, while returning to B restores B's draft.
