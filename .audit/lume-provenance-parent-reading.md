## Candidate 2

Read the full package in bounded chunks, including the migration paragraphs omitted by a terminal truncation. It independently converges on a task-scoped generation call, immutable flattened obligations and central transactional writes/delivery.

Useful distinctions from candidate 1: it explicitly preserves the existing legacy human-artifact convention as a documented assumption, allows an eligible shared-task history for conversational follow-ups, omits an unknown knowledge usage note without dropping its traceable document, and permits a concrete same-audience connector adapter. It also makes hidden native-provider search ineligible only for the bounded invocation and separates processing endpoints from human delivery recipients.

Concerns remain about scope and migration. A cutover audience fence for unknown 0075 pages risks inventing sharing behavior unrelated to the requested case model. Deferred database binding triggers, a generic submission/policy/observation store and every private provider-step receipt still require a broad migration. Changing artifact history from sampled snapshots to a row for every autosave needs a product/data-volume reason. These mechanisms cannot be accepted only because they close a theoretical future bypass. The comparison must distinguish required protection of application-known sources from claims to certify every historical byte.

The design's current-ACL atoms plus pinned historical obligations are coherent on paper. Their named locking protocol needs an actual mutation-call-site inventory and meaningful concurrent tests; a shared/exclusive lock added only to the new service would be ineffective. The default 256-obligation limit is a proposed execution limit, not measured evidence, and must not create accidental denial in ordinary cases.

No base has been selected. Candidate 3 and the independent cross-judge remain required. Shared generation consensus does not automatically accept either candidate's surrounding general content platform.
