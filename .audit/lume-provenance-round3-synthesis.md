## Closed data and edit contract

ContentResult<T> is server-owned value + complete policies + immutable domain identities + canonical payload digest. Affected research/settings producers must return it, including null/empty metadata projections. DTO mapping and both schema parses preserve the root exposure. Existing exact artifact/page/document/annex capture adapters may remain. Do not require a wholesale migration of unrelated private tools. Remove the known shallow research/settings capture and reloading fallbacks in this wave.

Research has fixed scalar slots legalQuestion/objective/thesis, selected document identities, and bounded documented/alleged/gap entries. Each stored part has stable entry identity, canonical value digest, retained ContentPolicy and contribution receipt. Generation conservatively assigns all actual generation contributors to each output part. Models cannot declare independence or attribution.

ProfileView is an explicit complete/restricted union. Shared metadata (caseId, revision, current visible document identities, server readToken) is common. Visible scalar parts are distinguishable from withheld scalar parts; required business fields must not be fabricated as empty valid values. Lists return visible stable IDs and a neutral withheld count/flag; never hidden text. The capability schemas and actual form must understand this union.

Validated human edits use server-sealed standalone form input plus readToken/seed. They do not require a chat conversation or content_submission row. Use content_seed for the shown revision, entry identities, digest and baseline policies. Persist the receipt with the owning revision transaction. Direct human form flow has no new approval step.

For existing resources require revision CAS and the shown read token. Submitted visible entries retain their IDs; omission deletes only entries the token showed and permits editing. Hidden entries remain unchanged. Trimming, blank filtering, reordering and changing documented/alleged category must preserve identity. A changed entry carries its prior/seed obligations; unchanged entries retain exactly their existing policy. New entries receive fresh server IDs and authenticated input policy, without unioning unrelated entries. Missing, duplicated, unknown or transplanted IDs/tokens conflict. The server must not accept dropping IDs as a declaration of fresh independent replacement of an existing seeded value. Explicit fresh replacement is an authenticated request without prior content selected, exact review and CAS, retaining old history.

ResearchTextChange is a finite person/request/confirm union, consumed by canonical profile/reference commands. Planner arguments may select resources, operation and expected revision, but not supply shared freeform fields, titles, notes or rationale. A request resolves the current authenticated person submission. A confirmation resolves an exact persisted proposal receipt. Existing reference linkage/purpose-only edits or omitted notes preserve prior text and policy and need no model call.

ResearchGenerationReceipt is a finite profile/notes persisted output discriminator with schemaVersion, target identity + expected revision, generationAttemptId, input digest, output digest, exact structured output and field policies. The research contract validates it; callers cannot construct a trusted receipt. Reuse content_generation_attempt and the existing submission/generation/operation tuple, with research target/schema identity added. No new general generation lifecycle.

## Assessment content identity versus execution identity

Keep inputFingerprint as content identity (exact immutable bytes/pins, profile revision, material version, questions/config). It is not enough to identify queued work. Add request/execution identity derived from original user, original session, invocation/case context and the admitted request operation or submission identity. Do not use only user ID. Preserve that authority under worker lease recovery.

Drop the old content-only unique constraint through a new migration and replace it with execution-aware uniqueness. Same logical request retries reuse their attempt. Independent later authenticated requests can enqueue the same content under their own authority. Never overwrite a running row's original requester/session. An expired request becomes unavailable; a new request is not permanently blocked by it.

Authorized completed-result reuse is a read: authorize its retained exact policy under the new reader and return the historical identity. It does not reopen that old row as work with the new person's session. Simplest acceptable implementation is request-scoped reuse only; cross-request completed reuse is optional, not required optimization. Preserve all old rows. Legacy queued rows without recoverable original authority must not send; the user can request a fresh assessment.

## Admission and denial semantics

Source-bearing structured and TypeSafe APIs require an owner-created admission. Administrative fixed probes/application-only requests use a separate trusted form; no caller-selectable sourceFree boolean or optional admission fallback. Snapshot prompt, instructions, schema, images and input digest before asynchronous preparation. Request-local adapter binds each concrete wire body to that immutable invocation. Application and wire digests are distinct; SDK serialization and generated repair output do not equal the original prompt bytes. No transcript, tools, memory or private provider continuation is allowed in shared generation.

After staging, credentials, credits/configuration, budget reservations, backoff and SDK request preparation, the concrete fetch wrapper runs current session/capability/source/lease/cancellation checks in a short ACL transaction. Recheck clock_timestamp session expiry after lock waits. Then enter actual fetch without another application wait. Never hold the ACL gate during network I/O. Current sender/source authorization for Google and email runs at their concrete existing transport guard.

Use one request-local denial latch retaining the original domain error when an SDK wraps/returns it. The guard records denial before throwing; later retries immediately fail from that latch. Runtime checks the latch on returned result and caught error and rethrows the original authorization/cancellation failure after finalization. Do not inspect error message text, expose source details, increment provider failure/circuit counters or return degraded authorized-looking content on denial.

TypeSafe finalizes its evaluation with a safe denial reason and no response before rethrowing. Release a reservation only when transport never entered; retain conservative accounting for prior attempted/ambiguous calls. AI usage retains failed/denied classification without pretending the provider was unhealthy. Failure to finalize must not turn denial into success. Injected test send functions sit behind the same admission. Tests must capture actual transport entries.

Admission is a local boundary. It cannot atomically commit PostgreSQL and remote disclosure, retract already sent bytes, or guarantee a revocation racing after successful admission cancels them.

## Managed files and legacy compatibility

Binding includes exact document/version/versionId, hash, size, original contribution receipt, access policy and disclosure policy. Access always retains source document/observed ancestors and derivation. Disclosure normally retains all obligations. Only independently contributed own original can omit its own container obligations for recipients. Actual pinned-version author and contribution evidence decide this; a latest writer, folder reader, import, generated export, managed copy, edit or prefill is insufficient.

Gmail, remote draft attachment reuse, Drive replacement, personal share metadata/claim/read and deferred email retain this binding. Verify staged digest/size and exact version before dispatch/read. Original session is needed for creation/deferred sends and retries; later authorized share reading uses recipient session and sender's continuing source access, not an eternally logged-in sender. Do not incorrectly require an outside recipient of an own original to join the sender's private case.

Use additive version contribution metadata where existing history cannot distinguish independent upload from derivation. Recover old bindings only from reliable records. Missing/contradictory authorship never grants an own-original exception. Preserve recognized legacy-human convention only with explicit historical evidence and report the compatibility assumption. Unknown old shares cannot manufacture a new exception.

Legacy research text is retained. Recover only trustworthy prior human submission/generation receipts and all known guards. Latest editor/reviewer is not the author. If actual author cannot be established, withhold unknown text for everyone, retain neutral metadata and allow a fresh admitted request. If known author but unresolved provenance, owner-only uncertainty plus known guards may preserve private visibility. Do not quarantine unrelated human resources or applied pages. Old incomplete research replay denies cached bytes without repeating an effect; current canonical read can still project safely.
