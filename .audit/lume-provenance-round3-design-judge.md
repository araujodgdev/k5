**Recommended boundary and grafts**

Use C’s canonical `saveResearchCaseProfile(change)` and reference-note commands, backed by one research contribution contract. Research owns field meaning, seed interpretation, projection, evidence validation and retained policy. The existing writing mechanism owns authenticated chat input, generation attempts and transport execution.

Graft these narrowly:

- **B’s explicit restricted-profile projection and entry-token sidecar.** Existing profile output schemas require `legalQuestion` and `objective`; withholding either needs a declared partial view, not fabricated strings. The current form trims and filters arrays, so tokens must survive those transformations.
- **B’s distinction between application payload identity and provider wire identity**, plus mandatory admission for both SDK fetch and injected test transport.
- **A’s explicit assessment-coalescing warning** and narrowly shared `stageManagedFile` operation. Keep staging outside the policy algebra while using one canonical interpretation of access and disclosure.
- **C’s conversation-free form admission.** The installed schema confirms `content_submission` requires a conversation/message, while `content_seed` permits a research purpose and scope.

Reject the larger unified writer with domain commit handlers, a separate research attempt lifecycle, universal JSON policy traversal, row-wide profile policy, and private-only agent profile overlays. Moving a feature into private storage does not repair the accepted shared feature.

There are **genuinely distinct viable structures** in the candidate set. Domain-owned generation can reuse submission/runtime mechanisms while retaining research semantics. A central typed draft service could instead own generation and issue receipts consumed by research writers. Both can enforce policy, but the latter exposes proposal/application choreography and duplicates structured-resource knowledge. A separately persisted research generation lifecycle is another structural alternative, with unnecessary recovery duplication here.

**Necessary design edits before implementation**

1. **Specify actual factories for all eight providers.** [Current `modelFor`](C:/Users/douglas.araujo/Documents/dgstack/k5/apps/web/src/lib/ai-providers.ts:49) injects fetch only for CLIProxyAPI. Installed `createOpenAI` and `createGateway` expose fetch; Mastra accepts native language-model objects, but its router configuration has no fetch member. Anthropic/Google factories bundled in private Mastra chunks are not a supported application import contract. Name supported public factories, required dependencies, endpoint/protocol choices and retry settings. Every initial, retry, repair and secondary request must enter guarded HTTP transport. Unsupported wiring remains a blocker, not permission to remove a configured provider.

2. **Make admission required and preserve its failure identity.** Protected calls must have owner-created authority; source-free calls need a separate trusted form. Brands and restricted imports help guide callers but cannot establish origin. Installed TypeSafe wraps fetch failures in `APIConnectionError`; [the application catch](C:/Users/douglas.araujo/Documents/dgstack/k5/apps/web/src/lib/typesafe/client.ts:81) currently increments provider failures. Define how admission denial escapes SDK wrapping, finalizes accounting and propagates without degraded success. `ai-runtime` also currently replaces authorization errors with a generic IA error.

3. **Resolve assessment deduplication versus requester ownership.** [The current queue](C:/Users/douglas.araujo/Documents/dgstack/k5/apps/web/src/lib/research/case-assessment.ts:141) reuses rows by office/case/material/input fingerprint, regardless of requester/session. Define an execution identity distinct from content identity. A new independently admitted request must neither acquire the first requester’s authority nor become permanently blocked by that requester’s expired session. Authorized completed-result reuse and queued-work reuse require separate rules.

4. **Integrate one exact review at the correct point.** [`runCapability`](C:/Users/douglas.araujo/Documents/dgstack/k5/apps/web/src/lib/agent-tools/index.ts:280) performs central confirmation before the executor. Generated research must prepare and retain the exact structured payload before that review, then commit it by receipt. Avoid a selector-only approval followed by another content approval. Direct human form editing keeps its existing flow; no per-field confirmation or operator approval is needed.

5. **Finish the concrete edit and result contracts.** Define C’s `ProfileView`, validated patch and generation receipt types. Specify stable entry correspondence, hidden-entry preservation, documented-to-alleged moves, missing-token handling and fresh replacement admission. Require complete policies through reference nesting, both output parses, approval outcomes, replay, private derivation and history. Delete affected shape-guessing fallbacks in the same migration wave.

6. **Tighten legacy and delivery rules.** Missing reliable author identity means withheld legacy text, not ownership assigned from the latest editor. Old shares/operations with unrecoverable bindings must not receive an own-original exception. Gmail draft reuse, Drive replacement, share metadata/claim/read and deferred email must retain exact version, digest, sender access and recipient disclosure separately. A legitimately disclosed own original must remain readable outside its private case.

With these edits, the chosen interface can close all nine groups without a universal rewrite. Each invariant has a bounded owner, and fresh requests avoid lifetime source unions.
