# PDFcn para geração de PDFs pelo Lume

Pesquisa em 03/10/2026. Este documento fundamenta a etapa de PDF do [relatório de refinamentos do agente, memória e revisão](../plano-refinos-agente-memoria-e-revisao.md). A pesquisa consultou documentação oficial, código dos projetos e a base inicial do Lume. Depois da pesquisa, a integração PDFcn/Forme 0.27.0 foi implementada e passou em testes Node e e2e, com paginação, pt-BR, tabelas e links. O relatório consolidado registra a implementação e as limitações; as propostas abaixo preservam o raciocínio da pesquisa inicial.

## Recomendação

Adotar os componentes PDFcn da base `forme/`, com `@formepdf/react` e `@formepdf/core`, para gerar PDFs novos a partir de versões dos artefatos do Lume. A primeira prova deve usar o processador Node/Container existente. Recomenda-se testar as versões exatas `0.27.0` dos dois pacotes, publicadas no momento da pesquisa, e fixar as versões aprovadas no lockfile. O registry do PDFcn instala essas dependências para a base Forme; o core atual tem entradas distintas para Node e Workers. A escolha é uma recomendação de arquitetura, ainda sujeita à prova com documentos reais do Lume. [Instalação PDFcn](https://www.pdfcn.dev/docs/installation), [registry Forme inspecionado](https://github.com/shadcn-labs/pdfcn/blob/39c75c1abbbad7b89ad1d8d3ea740ef635818a4b/apps/web/public/r/forme/text.json), [core 0.27.0](https://registry.npmjs.org/@formepdf/core/0.27.0), [React 0.27.0](https://registry.npmjs.org/@formepdf/react/0.27.0).

O motivo da preferência é o contrato voltado a documentos: primitives em pontos, páginas A4, tabelas, elementos fixos e controle de quebra. A base Forme do PDFcn envolve diretamente os componentes `@formepdf/react`; há menos tradução entre as medidas do documento e o renderer. O wrapper Takumi do PDFcn converte pontos para pixels CSS e traduz algumas propriedades de página. Isso favorece Forme para as minutas e relatórios desta etapa, mas não demonstra superioridade de desempenho ou de qualidade. [Primitives Forme](https://github.com/shadcn-labs/pdfcn/blob/39c75c1abbbad7b89ad1d8d3ea740ef635818a4b/apps/web/registry/bases/forme/lib/pdf-primitives.tsx), [primitives Takumi](https://github.com/shadcn-labs/pdfcn/blob/39c75c1abbbad7b89ad1d8d3ea740ef635818a4b/apps/web/registry/bases/takumi/lib/pdf-primitives.tsx), [componentes Forme](https://docs.formepdf.com/components), [paginação Forme](https://docs.formepdf.com/page-breaks).

Preservar a exportação DOCX e o caminho DOCX → LibreOffice → PDF quando a pessoa exigir o modelo Word cadastrado. PDFcn deve acrescentar uma opção de geração com layout PDF próprio. A análise atual não sustenta uma substituição integral do conversor existente. [Exportação DOCX do Lume](../../apps/web/src/lib/document-export.ts), [conversão PDF atual](../../apps/web/src/lib/document-pdf-node.ts).

## O que o PDFcn fornece

PDFcn é um registry de componentes React para copiar para o projeto, no modelo shadcn. Suas bases atuais são Takumi e Forme; componentes, blocos e temas ficam sob controle do código consumidor. Ele não fornece por si só a ferramenta do agente, autorização, persistência ou armazenamento dos PDFs do Lume. [Introdução PDFcn](https://www.pdfcn.dev/docs), [registry](https://www.pdfcn.dev/docs/registry).

Na futura implementação, executar da raiz o fluxo pnpm/shadcn direcionado ao aplicativo e revisar os arquivos gerados. A documentação exemplifica `pnpm dlx shadcn@latest add @pdfcn/forme/text`, usa `@pdfcn/forme/<componente>` e manda importar `Document` e `Page` de `@formepdf/react`. Os comandos ficam registrados como referência; não foram executados. [Instalação](https://www.pdfcn.dev/docs/installation), [regra pnpm do projeto](../../AGENTS.md).

Copiar somente os componentes usados pelo layout inicial, como texto, títulos, listas, tabelas, links, cabeçalho, rodapé, número de página e imagens. A lista oficial também inclui `Keep Together` e `Page Break`. Não há necessidade de adicionar todas as dependências do site de demonstração do PDFcn. O registry Forme de texto declara core e React; o registry Takumi declara `takumi-pdf` e helpers. [Índice oficial](https://www.pdfcn.dev/llms.txt), [registry Forme](https://github.com/shadcn-labs/pdfcn/blob/39c75c1abbbad7b89ad1d8d3ea740ef635818a4b/apps/web/public/r/forme/text.json), [registry Takumi](https://github.com/shadcn-labs/pdfcn/blob/39c75c1abbbad7b89ad1d8d3ea740ef635818a4b/apps/web/public/r/takumi/text.json).

## Capacidade necessária para os documentos do Lume

| Necessidade | Evidência e consequência para a implementação |
| --- | --- |
| Texto selecionável e pesquisável | O Forme tem testes oficiais que renderizam e extraem texto Unicode com PDF.js e, quando disponível, `pdftotext`. Isso sustenta testar a preservação de texto, em vez de produzir páginas como imagens. Acentos pt-BR precisam passar pelo corpus local. [Teste de extração](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/tests/unicode-extraction.test.ts). |
| Links clicáveis | PDFcn tem `Link href`; Forme também oferece links em texto e containers. Seus testes verificam anotações de link. Validar os destinos extraídos do PDF final. [PDFcn Link](https://www.pdfcn.dev/docs/components/forme/link), [teste de links](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/tests/pdfua-link-tagging.test.ts). |
| Várias páginas e tabelas | Forme documenta quebras entre filhos, linhas de tabela e linhas de texto; `Row header` repete o cabeçalho de tabela nas páginas de continuação. Manter assinaturas e trechos curtos juntos com `wrap={false}`, sem envolver a minuta inteira nessa regra. [Paginação](https://docs.formepdf.com/page-breaks), [Table PDFcn](https://www.pdfcn.dev/docs/components/forme/table). |
| Cabeçalhos, rodapés e numeração | `Fixed` repete conteúdo e reserva espaço na página; a documentação usa marcadores de página atual e total. No PDFcn, `PageHeader.fixed` e `PageFooter.fixed` são `false` por padrão. Configurar explicitamente e testar as páginas de continuação. [Fixed](https://docs.formepdf.com/page-breaks), [PageHeader](https://www.pdfcn.dev/docs/components/forme/page-header), [PageFooter](https://www.pdfcn.dev/docs/components/forme/page-footer). |
| A4 e tipografia jurídica | Forme aceita `Page size="A4"`, margens em pontos e alinhamento justificado. Proposta do Lume: preset jurídico com margens, corpo, espaçamento, recuo, títulos e timbrado definidos pela equipe; ajustes do renderer não equivalem a aprovação jurídica. [Page](https://docs.formepdf.com/components), [estilos](https://docs.formepdf.com/styles). |
| Fontes e pt-BR | Forme registra fontes e embute subconjuntos dos glifos usados. Adotar arquivos de fonte aprovados e licenciados, incluindo variantes normal, negrito e itálico; testar `ação`, `órgão`, `São Paulo`, `º`, `§` e `R$`. O core Node atual lê fontes de caminho local ou bytes, enquanto a documentação também mostra URLs. Fornecer bytes controlados evita depender dessa diferença. [Fontes](https://docs.formepdf.com/fonts), [resolução Node](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/src/index.ts). |
| Imagens e SVG | Forme documenta JPEG/PNG e SVG vetorial com formas básicas. A FAQ informa que filtros, gradientes e máscaras SVG não são suportados. Para um logo com recursos fora desse conjunto, preparar um PNG aprovado. [Image e Svg](https://docs.formepdf.com/components), [limites SVG](https://docs.formepdf.com/faq). |

## Engines, servidor e custo

| Opção | Situação verificada | Uso proposto |
| --- | --- | --- |
| PDFcn Forme + core local | O motor roda via WASM. `renderDocument()` recebe o elemento React e devolve `Uint8Array`; a documentação declara uso em rotas e server actions do Next.js. O core 0.27.0 suporta React 18/19 e depende do adapter React. [Quickstart](https://docs.formepdf.com/quickstart), [Next.js](https://docs.formepdf.com/faq), [manifesto core](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/package.json). | Primeira opção. Renderizar no Node/Container que já processa documentos no Lume; provar também o build de produção do aplicativo. |
| Forme em Worker | O entry oficial exige importar o módulo WASM e chamar `await init(wasm)` antes de renderizar; a inicialização é idempotente. Há testes oficiais em workerd. Esse suporte do pacote não verifica vinext, Wrangler, bindings e carga real do Lume. [Entry Worker](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/src/worker.ts), [testes workerd](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/tests/worker.test.ts). | Avaliar depois da prova no processador. Medir memória, CPU, WASM e bundle completo; não prometer execução direta no Worker web. |
| Forme em servidor próprio | A documentação oferece container HTTP com `/v1/render`; templates JSX são compilados para JSON antes de chegar ao servidor Rust. Existe autenticação Bearer opcional. [Self-hosting](https://docs.formepdf.com/self-hosting), [template mode](https://docs.formepdf.com/template-mode). | Alternativa se o renderer precisar de isolamento operacional. Preferir o processador já existente para evitar um serviço adicional sem necessidade comprovada. |
| PDFcn Takumi + `takumi-pdf` | Takumi atual gera PDFs com texto selecionável, fontes embutidas, A4 e WASM. Tem paginação, `<thead>` repetido e links, além de entrada `takumi-pdf/next` e documentação de Workers. Não deve ser confundido com um PDF composto de screenshots. [PDF Takumi](https://takumi.kane.tw/docs/pdf), [paginação](https://takumi.kane.tw/docs/pdf/pagination), [links](https://takumi.kane.tw/docs/pdf/links-and-outline). | Alternativa válida se Forme falhar no corpus ou na integração. Comparar os mesmos documentos antes de escolher por desempenho; os benchmarks oficiais são de versões e máquinas específicas. [Comparação](https://takumi.kane.tw/docs/pdf/comparison). |

PDFcn tem licença MIT. Forme declara todo o projeto MIT e informa que o serviço hospedado foi encerrado; renderização é local ou por servidor próprio. Portanto, não planejar assinatura ou cobrança por render de uma API hospedada Forme. O custo esperado é infraestrutura do Lume, armazenamento, processamento e operação, a medir. O pacote `takumi-pdf` atual declara licença MIT ou Apache-2.0. Preservar os avisos exigidos pelas licenças e conferir a licença de cada fonte. [Licença PDFcn](https://github.com/shadcn-labs/pdfcn/blob/39c75c1abbbad7b89ad1d8d3ea740ef635818a4b/LICENSE), [FAQ Forme](https://docs.formepdf.com/faq), [licença Forme](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/LICENSE), [manifesto Takumi 0.15.0](https://registry.npmjs.org/takumi-pdf/0.15.0).

## Base local no início da pesquisa

`exportDocument()` transforma Markdown em DOCX ou injeta o conteúdo em um modelo DOCX. O caminho de template preserva cabeçalhos, rodapés, relações, estilos e geometria final da seção, removendo o corpo factual anterior e metadados. O parser atual descarta o destino dos links ao exportar o texto. [document-export.ts](../../apps/web/src/lib/document-export.ts).

`exportPdf()` recebe DOCX e escolhe LibreOffice em Node ou RPC para o processador Cloudflare. O conversor remove macros, objetos embutidos e relações externas, aplica limite de entrada, timeout, valida o cabeçalho PDF e exige páginas. Há limite de duas conversões ativas no processo. [document-pdf.ts](../../apps/web/src/lib/document-pdf.ts), [document-pdf-node.ts](../../apps/web/src/lib/document-pdf-node.ts), [contrato](../../apps/web/src/lib/document-pdf-contract.ts), [processador](../../apps/web/src/workers/processors.ts).

A rota autenticada `/api/artifacts/[id]/export` aceita `format=docx|pdf`, confere propriedade do artefato, pode rejeitar versão divergente e verifica novamente a sessão após renderizar. O PDF dessa rota ainda deriva do DOCX; ela devolve bytes para download. A ferramenta `k5_artifacts_export_docx` apenas retorna um link DOCX e nome de arquivo, sem parâmetro de versão. [Rota export](../../apps/web/src/app/api/artifacts/[id]/export/route.ts), [serviço de artefatos](../../apps/web/src/lib/application/artifacts-service.ts), [contratos](../../apps/web/src/lib/capabilities/contracts.ts).

O Cofre já registra arquivo original, hash, tamanho, MIME e uma primeira versão ao criar o documento. A leitura de um modelo Word usa a autorização do Cofre antes de buscar o original. Esses mecanismos são o ponto de integração para persistir o PDF; a exportação de artefatos atual não os usa para salvar o resultado. [Cofre](../../apps/web/src/lib/vault.ts), [rota export](../../apps/web/src/app/api/artifacts/[id]/export/route.ts).

## Proposta de integração

As decisões abaixo são propostas para implementação, baseadas nos limites de autorização e versionamento existentes. [AGENTS.md](../../AGENTS.md), [serviço de artefatos](../../apps/web/src/lib/application/artifacts-service.ts), [Cofre](../../apps/web/src/lib/vault.ts).

1. Acrescentar `k5_artifacts_export_pdf`, no grupo de documentos, com `artifactId`, `version`, preset de layout e destino autorizado do Cofre. A sessão fornece usuário e escritório; o modelo não fornece `officeId`. Classificar como escrita quando a ferramenta cria o arquivo persistido. Separar essa ação do link de download, que é leitura.
2. Ler uma versão explícita e autorizada do artefato. Registrar título e conteúdo dessa versão, preset, versão do renderer e hashes das fontes/imagens. Uma mudança posterior no editor não pode trocar o conteúdo de um PDF já entregue. A resposta deve mostrar a versão exportada.
3. Converter Markdown para uma árvore de conteúdo validada e limitada. Renderizar essa árvore com componentes React fixos e revisados do Lume. O modelo pode fornecer conteúdo e escolher um preset permitido; nunca executar JSX, JavaScript, imports ou expressões enviados pelo modelo. O renderer e os layouts pertencem ao servidor.
4. Resolver imagens, fontes e timbrado no servidor a partir de arquivos controlados ou do Cofre com ACL. Passar bytes ou data URIs com limites de tamanho. Não aceitar caminhos arbitrários, URLs de assets do modelo ou tokens de armazenamento como conteúdo.
5. Guardar os bytes originais do PDF no storage do Cofre, com `application/pdf`, nome, tamanho e SHA-256. Criar documento e versão com provenance ligada à versão do artefato, conversa, usuário, layout e execução. A extração/indexação deve consumir esse mesmo original. Não reconstruir o PDF ao baixar uma versão salva.
6. Reservar idempotência por escritório, usuário, artefato, versão e intenção de exportação. Incluir layout e hashes de assets na identidade. Repetições e retries devem devolver o mesmo arquivo; conflitos com outra intenção devem falhar. Tratar falha entre storage e banco com estado de operação e reconciliação, sem deixar uma resposta que prometa um arquivo inexistente.
7. Validar acesso ao destino e ao original no momento da geração e do download, com a política já usada para o caso e as pastas acima. Associar ao chat um link autenticado para a versão do Cofre. Não colocar URL pública permanente nem bytes do PDF no contexto do modelo.
8. Gerar como documento sujeito à revisão humana. A confirmação de publicação, envio externo ou substituição deve cobrir a versão exata entregue. Uma nova geração não deve herdar a aprovação de uma versão anterior. A etapa de revisão deve seguir o plano consolidado.

Há um risco concreto em assets: o core Node atual faz `fetch()` para imagens HTTP/HTTPS e lê caminhos locais para fontes; o helper Worker faz `fetch()` para fontes e imagens. Esses trechos não demonstram bloqueio de redes privadas, redirecionamentos ou limites de download. A aplicação precisa controlar a entrada antes do renderer para evitar SSRF e leitura de arquivos indevidos. [Resolução Node](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/src/index.ts), [resolução Worker](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/src/shared/browserHelpers.ts).

O provider Forme copiado pelo PDFcn usa uma variável de módulo `serializedTheme`. Isso exige testar temas alternados e renders de escritórios diferentes; não presumir isolamento de tema. A proposta é usar configuração explícita por documento e adaptar o código copiado se o teste demonstrar interferência. [Provider inspecionado](https://github.com/shadcn-labs/pdfcn/blob/39c75c1abbbad7b89ad1d8d3ea740ef635818a4b/apps/web/registry/bases/forme/components/theme-provider.tsx).

## Modelos Word e limite da migração

Os templates documentados pelo PDFcn são componentes React; o template mode do Forme compila JSX para JSON. As fontes consultadas não documentam importação de `.docx` que preserve todas as seções, campos, numeração, cabeçalhos e rodapés Word. Não assumir essa compatibilidade. Um timbrado PDF próprio deve ser cadastrado como um layout controlado, com logo e parâmetros aprovados. [Instalação e blocos PDFcn](https://www.pdfcn.dev/docs/installation), [template mode Forme](https://docs.formepdf.com/template-mode).

Quando houver modelo DOCX, manter o resultado atual disponível e indicar qual layout gerou cada PDF. Uma migração de modelo Word para preset PDF exige comparar os documentos e obter a escolha da pessoa, sem converter silenciosamente. Isso preserva a capacidade existente de exportar DOCX editável e PDF no timbrado Word. [Implementação atual](../../apps/web/src/lib/document-export.ts), [rota de exportação](../../apps/web/src/app/api/artifacts/[id]/export/route.ts).

## Prova de viabilidade futura

Critérios propostos para liberar a implementação, sem prova de execução nesta pesquisa:

- Renderizar em Node/Container uma minuta A4 curta, uma de 15 páginas e uma tabela longa. Incluir títulos no fim da página, lista numerada, citação longa, assinatura, cabeçalho/rodapé e links. Testar também documento vazio, imagem inválida e conteúdo acima dos limites.
- Extrair o texto de todas as páginas com PDF.js ou `pdftotext` e comparar com o conteúdo esperado, incluindo caracteres pt-BR. Extrair anotações e conferir destinos dos links; validar número de páginas, tamanho A4 e fontes embutidas. Os testes oficiais Forme já usam extração como verificação. [Teste Unicode](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/tests/unicode-extraction.test.ts).
- Renderizar as páginas como imagens para conferência visual do advogado. Verificar cortes, espaços, tabelas, numeração e timbrado. A leitura de texto não prova que o layout está correto. O Forme oferece metadados de layout para automatizar parte da verificação. [Layout API](https://docs.formepdf.com/layout).
- Exercitar duas gerações simultâneas, temas diferentes, retry idempotente, falha depois do upload, mudança de versão, logout durante geração e download após revogação de acesso. Confirmar que o SHA-256 do download corresponde aos bytes persistidos.
- Verificar o build Next e o processador de produção com a versão fixada. Depois, testar uma rota isolada em workerd/Workers com import e `init` oficiais, sem divulgar conteúdo real. Medir bundle, pico de memória, CPU, cold start e tempo de render; documentar os limites aprovados. [Entry e inicialização oficiais](https://github.com/danmolitor/forme/blob/b973bfc8ca296e2a2f2f7ae939981a3598e53c91/packages/core/src/worker.ts).
- Manter os testes do caminho DOCX/LibreOffice. Adicionar teste de fluxo para gerar pelo chat, revisar, salvar no Cofre e baixar a versão correta em desktop e mobile, seguindo os checks do projeto. [Validação do projeto](../../AGENTS.md), [e2e de exportação existente](../../apps/web/e2e/document-pdf.e2e.ts).

Resultado esperado da prova: PDF com texto extraível, links corretos, paginação legível e bytes persistidos sob ACL, sem executar código do modelo. Se o corpus falhar no Forme, comparar o mesmo corpus com `takumi-pdf`; se só o Worker falhar, manter a geração no processador Node/Container. Essas são decisões propostas, não resultados já verificados.
